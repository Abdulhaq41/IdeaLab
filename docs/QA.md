## Что покрывают 27 тестов

Подпись/возраст/подмена initData; запрет demo в production; подпись и срок сессии; каждый шаг обучения и его восстановление; идемпотентность и повтор ID с другим телом; улучшение ровно один раз; серверный seed; ограничения запасов и ёмкости; финализация один раз после повторного открытия SQLite; отсутствие аренды за 90 дней отсутствия; решение только для будущих заказов; столкновения, дверь, рабочая точка и пути; склад и схемы; бесплатное восстановление без бесконечных наград; 30 уникальных событий и 12 эффектов; владелец/сумма/валюта/payload платежа; параллельная покупка; повтор successful-payment на уровне сервиса; глобальная уникальность charge ID; источники прав, возврат, повтор возврата и продление Plus; отсутствие чужого доступа через HTTP; серверный admin allowlist; реальные PostgreSQL-конфликты; первые три смены с сохранением; атомарность аудита; запас молока не блокирует зёрна; транзакционная квота ИИ; истечение Plus; открытия глав и ветки историй.

Отдельно исправлен финансовый тупик: платное оперативное решение не может потратить резерв зарплаты/аренды и помешать финализации убыточной смены.

## Экономическая симуляция

По 1 000 независимых seed на вариант, одинаковые полные запасы, начальная репутация, одна команда. Эти числа — результаты моделирования игровой конфигурации, не прогноз реального дохода.

| Стратегия        | Базовая прибыль/смену | С улучшениями | Доля обслуженных: база → улучшения |
| ---------------- | --------------------: | ------------: | ---------------------------------: |
| По-соседски      |                 1 240 |         2 793 |                      54,0% → 73,9% |
| Золотая середина |                 1 511 |         3 404 |                      67,7% → 92,3% |
| Авторский подход |                 1 898 |         3 306 |                      81,0% → 86,8% |

Низкая цена повышает спрос и рост репутации, авторская — средний чек с отказами чувствительных к цене гостей. Улучшения увеличили прибыль и долю обслуженных во всех трёх вариантах. Большое абсолютное число потерянных гостей при расширенном спросе само по себе не означает ухудшения: проверяется также доля обслуживания. Сервер запрещает мгновенные повторные выплаты и не предоставляет клиентского ускорения времени.

## Явные сокращения и ограничения

- Комната остаётся 9×8 во всех трёх главах. Меняются детали сцены и открываются истории; расширение физического помещения не реализовано. Предметы сохраняются.
- Анимации процедурные: маршруты, покачивание/шаг, работа, пар, реакция заказа и эффект улучшения. Отдельных рисованных покадровых наборов нет.
- Каталог в кабинете доступен для просмотра. Редактирование цен — через `shared/content.ts` с новой сборкой, только для будущих заказов.
- Настройка качества адаптируется по нагрузке и имеет ручной бережный режим, но стабильные FPS на физическом телефоне не замерялись. Проверка Chromium не заменяет iOS/Android Telegram.
- Журнал/агрегат пока без архивирования и серверной пагинации; нагрузочное тестирование и большой продакшен-трафик не проверялись.
- Уведомление имеет максимум одну сохранённую попытку отправки. При сбое сети оно может не дойти; автоматического повторного спама нет, отчёт не теряется.
- Семантику внешнего ИИ нельзя полностью доказать фильтром чисел. При сомнительном ответе используется шаблон; для публичного запуска нужны собственные контрольные примеры и лимит расходов у провайдера.
- Сайт официальной Telegram-документации закрыт сетевой политикой среды; текущий официальный исходный код Bot API прочитан. Перед реальными продажами обязательно выполнить [Telegram-прогон](TELEGRAM.md) по актуальной документации.
- Production ещё не развёрнут, BotFather/HTTPS/webhook не настроены, резервная копия production не восстанавливалась. Инструкции и безопасные маршруты подготовлены.
